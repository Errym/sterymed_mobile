# SteryMed Mobile — The Complete Build Breakdown

# Senior mobile engineer's master plan · Backend ready · UI provided · Flutter · 55 days + 8 contingency · Pilot MVP

This is the entire project, phase per phase, from Day 1 to Day 55 and handoff. Every decision is justified. Every phase has entry criteria, daily work, exit criteria, and tests. Every gate is binary. If you follow this exactly, you ship a working app that matches the backend, matches the web UI, matches the *Cahier des charges*, and passes pilot acceptance.

No fantasies. No invented scope. No over-engineering. Just the app the clinic will use.

---

# Part 1 — Ground rules

Read these once. Obey them for the entire project.

1. **The backend is the contract.** Observed API responses are the source of truth. Never trust DTOs in `openapi.yaml` over the wire.
2. **The web UI is the reference.** Match it visually. Do not invent new patterns for mobile when the web already has one.
3. **The brief is the scope.** No screen, no feature, no button that isn't in the brief. If it's not asked for, do not build it.
4. **The pilot is French-only.** No `app_en.arb`. No English strings anywhere. Ever.
5. **The pilot has two roles.** `admin` and `staff`. Not six. Not four. Two.
6. **The outbox is mandatory from Phase 5 onward.** Not bolted on later.
7. **The 409 is success, not error.** Replayed idempotency keys mean "already recorded."
8. **Blocking UI states come from the server.** Expired and recalled labels are decided server-side. Never client-side.
9. **No PII in logs.** Ever. Enforce at the interceptor level. Verify on Day 46.
10. **CI is proven on Day 6.** Not Day 47. If the pipeline is broken, everything after is chaos.
11. **Backup and restore are scheduled.** Not a checklist line. Drilled twice.
12. **Every gate is binary.** Pass or fail. No partial credit.
13. **Web + mobile coherence is tested continuously.** Not once at the end.
14. **If a phase slips, cut scope, not quality.** The cut order is at the end of this document.
15. **The pilot is a promise.** If the app loses a nurse's data entry, the pilot fails. Build accordingly.

**Error catalog.** Trigger each error on purpose. Record exact `error.code` and French `error.message`:

- 401 wrong password
- 403 staff hitting admin-only endpoint
- 404 unknown resource
- 409 idempotency replay
- 422 invalid payload
- 429 rate limit

Write `docs/ERROR_MATRIX.md`.

# Part 4 — Phase 1: Foundation (Days 4–6)

## Purpose

Build the plumbing every feature will use. No features. Only infrastructure.

## Day 4 — Network + storage

**`lib/core/config/env.dart`**

```dart
class Env {
  static const apiBaseUrl = String.fromEnvironment('API_BASE_URL');
  static const environment = String.fromEnvironment('ENV', defaultValue: 'dev');
  static const sentryDsn = String.fromEnvironment('SENTRY_DSN');
}
```

**`lib/core/config/api_endpoints.dart`**

One file, every path. Mirrors `routes/api.php` exactly. No strings scattered.

**`lib/core/network/dio_client.dart`**

Timeouts, JSON headers, base URL from Env.

**Interceptors**

- `auth_interceptor.dart` — reads bearer from `TokenStorage`, attaches to every request
- `error_interceptor.dart` — parses `{error:{code,message,details,request_id}}`, throws `ApiException`
- `idempotency_interceptor.dart` — injects `Idempotency-Key` on queuable POSTs
- `logging_interceptor.dart` — debug only, runs payload through `pii_scrubber.dart`

**`lib/core/storage/token_storage.dart`**

`flutter_secure_storage` for bearer. Nothing else.

**`lib/core/storage/session_store.dart`**

Holds current `UserData`, `TenantData`, current role. Wiped on logout.

## Day 5 — Errors, theme, router, DI

**`lib/core/errors/api_exception.dart`**

```dart
class ApiException implements Exception {
  final String code;
  final String message;   // French
  final Map<String, dynamic> details;
  final String requestId;
  final int? statusCode;
}
```

**`lib/core/errors/error_mapper.dart`**

`DioException` → `ApiException`. Handles network down, timeout, unknown server error.

**`lib/core/theme/`**

Match SteryMed UI colors, typography, spacing exactly. Pull tokens from the doc. Do not invent.

**`lib/shared/widgets/`**

The shared widget kit that every feature reuses. Full list in Part 6.

**`lib/core/router/app_router.dart`**

go_router with auth redirect. Route names in `route_names.dart`. Guards: `auth_guard.dart`, `role_guard.dart`.

**`lib/di/`**

get_it registrations split by concern.

# Part 8 — Phase 5: Usage + patients + offline outbox (Days 20–26)

This is the phase that makes or breaks the app.

## Day 20 — Patients

`PatientData` model. Debounced `GET /patients`. Selection UI as bottom sheet.

## Day 21 — Usage form

`LabelUsageFormScreen`:

- Label summary (read-only)
- Patient picker
- Procedure
- Notes
- `practitioner_id` = current user

`POST /labels/{label}/usage` with tap-time `Idempotency-Key`.

## Day 22 — Outbox core

`lib/core/storage/outbox/`:

- `outbox_item.dart` — `{id, operation_type, payload, idempotency_key, created_at, retry_count, status}`
- `outbox_store.dart` — hive-backed
- `sync_engine.dart` — flush on app start + connectivity restore. Ordered, one-at-a-time. Max 5 retries then manual review.
- `sync_result.dart` — success, conflict, error, manual review

`lib/core/sync/`:

- `connectivity_service.dart` — wraps `connectivity_plus`
- `sync_status_cubit.dart` — global sync state (pending count, online/offline)

## Day 23 — Submit routing

Online → direct POST. Offline → queue + pending state.

Form state preserved. If app killed mid-form, restored from hive on restart. **Never lose input.**

## Day 24 — Conflict semantics

- **409** → "Enregistré précédemment" toast, mark done
- **422** → surface error, keep for review
- **403** → surface error, keep for review
- **5xx** → retry with backoff, keep for review after 5 attempts

Sync status badge in shell shows pending count.

## Day 25–26 — Mandatory flaky-network device days

Take phone. Airplane mode on/off mid-submit. Throttle 3G. Kill app mid-sync. Replay same idempotency key. Make server unreachable during flush.

Log results. Fix everything.

- [ ]  Offline usage queues and survives app kill
- [ ]  Sync on reconnect verified server-side
- [ ]  409 conflict proven with evidence
- [ ]  Double-tap impossible
- [ ]  Form state never lost
- [ ]  **Web shows same usage record after mobile sync** (coherence check #2)

4. **Outbox is core.** Not a feature.
5. **Sync status is first-class.** `core/sync/` exists from Day 1.
6. **Idempotency is an interceptor concern.**
7. **PII scrubber is enforced at interceptor level.**
8. **Prosthetic module is a first-class feature.**
9. **Waiting for placement is a dedicated screen.**
10. **Every screen handles four states.** `shared/widgets/feedback/` exists for this.
11. **Golden tests cover 4 critical screens.**
12. **CI proven on Day 6.**
13. **No certificate pinning in MVP.** Deferred to v1.1.
