This matrix follows the [fresh master plan](../CLINIC_READY_MASTER_PLAN.md), its original requirement review and current source. It does not describe a verified deployment. Backend source was read without changing it or running clinical requests.

## Evidence and interpretation

- [contract_snapshot.json](contract_snapshot.json) records **110 backend method/path declarations**, **99 mobile HTTP dispatch sites** (including two browser multipart sends, generic retry/replay and signed-file download), their source lines, and hashes. Multiple dispatch sites can call the same operation.
- The 28 mobile network source files and 190 backend route/controller/request/DTO/policy/error files checked for this contract still match the full source review hashes. [Source review inventory](../SOURCE_REVIEW_INVENTORY.csv) records the wider review; Phase 0's `source_baseline.json` records the implementation baseline separately.
- The only currently called fixed mobile method/path absent from API declarations is `POST /v1/auth/forgot-password`. This does **not** mean the other journeys are complete: semantic defects, absent required flows and uncaught DTO errors remain.
- Matrix paths are shorthand relative to `/v1` (for example `/tenants` means `/v1/tenants`); the configured base URL must supply the deployment's API prefix. The snapshot records complete `/v1/...` paths. Braced segments are route parameters. Proposed contracts have no invented route name.
- **Declared** means present in source, **gap** means absent or unsafe for the required purpose, and **unwired** means declared but unused by the current mobile flow. Every row still needs runtime acceptance.
- DTO names below refer to backend `app/Domain/**/Data` files. The snapshot links each operation to its actual controller, request validator and DTO source. These are summaries, not a replacement for validation rules. `page<T>` means the cursor collection and cursor metadata; `list<T>` means an array/collection, not a cursor page. Delete operations generally return no content.
- `M`, `B`, `J`, and `C` mean mobile, backend/web, joint, and clinic/product responsibility. Task IDs are the canonical master-plan IDs. Local `BD-*` records live in [Backend dependencies](BACKEND_DEPENDENCIES.md).

### Shared request and response rules

- Login, registration and invitation acceptance are public throttled routes. Other listed API routes run Sanctum authentication, tenant middleware and API throttling; clinical identity must come from the authorized session and validated tenant-owned references.
- Errors use `{error:{code,message,details,request_id}}` in `app/Support/Api/ApiExceptionRenderer.php:41`. Named cases include401 `UNAUTHENTICATED`,403 `FORBIDDEN`,404 `NOT_FOUND`,422 `VALIDATION_FAILED` and429 `TOO_MANY_REQUESTS`; domain errors preserve their own code. Generic aborts may use `HTTP_<status>` or `CONFLICT`/`GONE`. Inspect code and status together; do not treat every409 as already completed or every401 as bad credentials.
- Do not wrap every success in the same guessed envelope: individual DTOs, arrays, cursor collections, no-content deletes and binary downloads differ. Current mobile cursor decoding reads `meta.next_cursor`. Runtime fixtures must pin the actual wire shape and every required field.
- PATCH omission and explicit null are different operations; submit only authorized changed fields. Decimal/date parsing, foreign/archived references and maximum upload size are validator contracts, not UI-only checks.

## G01 acceptance and change control

1. Every required journey above has an owning task and a declared, unwired or missing contract. Backend dependencies are local records, not external tickets or deployed changes.
2. Before implementing a new API, record method/path, permission, request rules, response/error shape, pagination and retry semantics here and in a schema fixture; agree it with its backend owner. Do not let a mobile workaround become an undocumented contract.
3. Current idempotency is finite and non-atomic: a user/key cache entry lasts86400 seconds; it hashes method/path/raw JSON bytes, omits tenant from the cache key, skips multipart caching and can cache error responses. PATCH/DELETE and some POST routes lack this middleware. **BD-08/O04** must resolve concurrency, retention, failure and reconciliation before durable replay can claim safety.
4. Existing declarations are checked by source fingerprints. Runtime acceptance needs the isolated two-tenant/six-role fixture set, actual request/response checks and server readback under **G03, V01–V04**. A path-only snapshot or a green mock test does not satisfy that gate.
5. **Status:** G01 engineering artifacts delivered; clinic decisions D03–D10 remain open where marked. Phase 0 exit must not claim these decisions were approved.
